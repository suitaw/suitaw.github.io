## vocab-ai-v5.html

英语 SRS 词汇学习应用，约 4300 行。

**三层结构**：`words.js`（内置词库）+ `nce.js`（新概念课程库）+ 主 HTML。
数据全在 `localStorage`，无后端。

**关键实现**：
- **FSRS-6** 间隔重复算法（2026-08 从 SM-2 换过来），评分四档：忘了/困难/记得/秒答
- 页面切换靠手写的 `go()` 和 `render()`，四个一级页面：学习 / AI 助手 / 复习·库 / 统计
- AI 请求统一走 `callAI()` 和 `callAIStream()`
- 五个 provider：DeepSeek、Kimi、OpenRouter、Anthropic、OpenAI，key 分开存

**FSRS 相关约定**：
- 21 个参数和全部公式照抄 `open-spaced-repetition/py-fsrs` 的 `fsrs/scheduler.py`，**不要凭记忆改数值**，要改先去核对源码
- 只实现长期公式，没有 Anki 那套 learning/relearning 分步队列——本应用队列是"忘了就塞回队尾"，没有分步概念
- `srs` 每条含 `s`(稳定性)/`d`(难度)/`lr`(上次复习)，同时继续维护 `due`/`interval`/`reps`/`lapses` 供旧 UI 读取，**别删这几个兼容字段**
- 不需要"提前复习保护"补丁了：同日重刷时 elapsed=0 → R=1 → 稳定性增量恰好为 0，FSRS 天然覆盖
- 换算法时旧 SM-2 进度转存在 `vocab_v5_srs_sm2backup`，`vocab_v5_fsrs_reset` 是防重复重置的标记位

**手机端适配的两条硬指标（2026-08-12 全站过了一遍，别再退回去）**：
- **字号地板 12px**：辅助文字 `.75rem`(12px)、次级正文 `.8rem`(12.8px)。
  原来散着 `.6/.62/.64/.66/.67/.68/.7/.72/.74rem` 九档、最小到 **9.6px**，共 71 处。
  这些**大半写在 JS 模板串的内联 style 里**，不是 CSS 类，改的时候要全文 sed 而不是只翻样式表
- **触控热区 44px**：改前实测底部导航按钮只有 **23px 高**（`.nav button` padding 才 4px），
  四个挨着，最容易点错。`.gear` 29、`.speak` 29、表单控件 36~38、滑杆 **16**、`summary` 21、拖拽把手 20
- **`--nav-h` 是唯一真相**：导航一变高，正文留白 / toast / 撤回条 / ＋词 FAB / 翻页箭头 /
  四处页内 `position:sticky` 的确认按钮**全得跟着挪**，原来是 72/84/72/134/64 六个硬编码数字散在各处。
  现在都写成 `calc(var(--nav-h) + 偏移)`，改热区只动 `:root` 里那一个数
- **角标类不要靠放大视觉来达标**：`.cat-tag` 撑到 40px 后在闪卡上跟单词抢戏。
  正解是视觉维持小胶囊、`::after` 用 `inset:-10px -9px` 把热区往外撑 ——
  实测视觉 83×27、真实可点 **101×47**。注意**按 `getBoundingClientRect` 量热区的脚本看不出这一层**，
  会误报成不达标
- 验证标准（脚本量过，结论如下）：390/360/320 三档宽度**均无横向溢出**；
  字号 <12px **0 处**；热区 <44px 从 89 处降到 5 类，剩下的是高度已达 44、宽 32~42 的图标钮

**智能体是多轮工具循环**（`agentRunLoop`，2026-08-12 从单轮改的，参考 ZeroTermux 的智能体）：
做一批动作 → **把执行结果回喂给模型** → 它再决定下一步。**"回喂"就是和单轮版的本质区别** ——
单轮时模型永远不知道自己那条动作干成了什么，也就没机会补下一步。
- **`agentExec` 必须返回结果字符串，失败也返回**（别只标红就吞掉）：模型要靠它改参数重试
- **空 `actions` 是唯一的正常出口**。系统提示词里得把这条说死，否则它会一直给动作、烧满轮数
- **动作按模型给的原序执行**，别拆成"先 safe 后 risky"——顺序是它排的（先 find 再 setCat），拆了因果颠倒
- **确认框改成了 Promise**（`agentAskConfirm` / `agentConfirmDone`）：循环得 `await` 在那儿等用户拍板。
  原来"攒起来等点执行"的单向流程在循环里没法用。**取消也要回喂给模型**，否则它下一轮原样再提一遍
- **`ui:1` 标记的动作执行完要 `agentMinimize()` 让开**（goTab/openCat/study/addWords/
  enrichPhonetics/reclassify/dedupe）。这是改造的起因：用户说"去背职场商务"，`study` 执行了、
  绿条也显示成功了，**但面板照旧盖着，屏幕上什么都没变**，他连问了两遍"？？""词呢?"。
  收起后靠 `.agent-bar` 悬浮条报进度、留「停止」
- **不要照抄 ZeroTermux 改成全屏页**：它的智能体操作终端（另一块屏，你切过去看），
  这个智能体操作 App 本身，动作结果就显示在被面板盖住的地方 —— 全屏只会让上面那个毛病更严重
- `agentBusy` 防重入（跑着时再点发送会开出第二个循环，两个都在改同一份 `agentHistory`）；
  `agentStop` 每轮开头查一次；图**只在第一轮带**（base64 每轮重发烧光 token）
- **`AGENT_TURNS` 必须声明在文件靠前的配置区，不能放智能体那一节**：`bindCfg()` 初始化时就读它，
  而智能体在文件最末尾 —— `const` 的暂时性死区会让整个页面初始化当场中断，
  报出来却是别处的 `Cannot access 'agentMini' before initialization`，看着像不相干的错。
  （和 cube-solver 那条 `goHome()` 早于 `let tuBorrow` 同源，栽第二次了）
- 上限档位 `[4,8,16,30]` 默认 8。**不用学 ZeroTermux 的 40**：那是装系统要反复读终端输出，
  这里动作集只有十几个、都是一步到位的本地操作，8 轮够；调大只在模型绕圈时多烧钱
- 验证手段：**打桩 `window.callAI`** 用脚本驱动循环（`callAI` 是全局 function 声明，可直接覆盖），
  不用真 Key 就能验多轮/回喂/让开/上限/确认/停止。四项都实测过

**版本号与「检查更新」**（`BUILD_STAMP` / `checkUpdate` / `hardReload`）：
版本号形如 `v5.4.0 · 日期 · 这次改了啥`，**改完必须顺手改它**，否则线上比对就失去意义。
- 设置页那颗「🔄 检查线上有没有新版」带时间戳 fetch 线上的自己，抠出版本号跟当前跑的比。
  光显示"当前正在跑哪版"回答不了"线上已经是哪版"——**缓存住的旧版显示的也是它自己的旧版本号**
- **抠版本号的正则必须拼出来，不能写成完整字面量**（`new RegExp("const BUILD_"+'STAMP="([^"]+)"')`）：
  抓下来的文件里既有真的声明、也有这行正则自己，写成字面量会先匹配到自己、抠出 `([^` 这种碎片。
  实测过：线上换成 v9.9.9 时抠出来的确实是 v9.9.9
- **失败路径不能静默当成"已是最新"**。`file://` 打开、断网、跨域都会 fetch 失败，
  必须明说"查不了，这不代表已是最新"（实测 file:// 下不误报）
- `location.reload(true)` 在现代浏览器里已是空操作，强刷得换 URL（`?v=时间戳`）

**踩过的坑，别再犯**：
- `callAIStream` 的 `onChunk` 收到的是**累积全文**，不是增量 —— 用 `=` 不是 `+=`
- 图片处理统一走 `readFileBytes`。vivo 相册交给浏览器的是 MediaStore 编号引用（`f.name` 是纯数字无扩展名）不是真实文件，用 `createObjectURL` 读一次失败后再用 `FileReader` 读同一个失效引用必然二次失败，还会吞掉真实错误。
